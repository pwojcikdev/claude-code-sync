Module desktop_sessions 

Source
Expand description

The Claude desktop app’s session list — what its Code tab shows in the sidebar.

The app keeps one JSON file per session under <app data>/claude-code-sessions/<org>/<account>/local_<id>.json, and a deleted_<transcript id> tombstone for every transcript whose session was deleted, so it never re-adopts that transcript from ~/.claude/projects. Syncing transcripts alone leaves the other machine’s sidebar empty: the app lists what its index holds, and only then finds the transcript by searching every project directory for <transcript id>.jsonl.

The app rewrites an entry on every focus and every turn, so two machines that both opened a session always hold two versions of its file. An overwrite or a hold-back would lose one side on every sync; instead both directions merge field by field (merge_index), three-way against the version this machine last synced when it still has it (see store_base), and otherwise letting the side with the later activity win. Tombstones only ever accumulate, and an entry whose transcript is tombstoned anywhere is removed everywhere.
